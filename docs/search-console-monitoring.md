# Search Console モニタリング & 改善サイクル

公開後 1〜2 週間程度経ったら、Google Search Console（GSC）と GA4 で実数値を見ながら改善していきます。
このドキュメントは **どの数字を、何を判断基準に、どう改善するか** の指針です。

## 1. 毎週見る数字（10分ルーチン）

### GSC「検索パフォーマンス」（過去 28 日 / 過去 7 日）
- 総インプレッション
- 総クリック数
- 平均 CTR（クリック率）
- 平均掲載順位

### GA4「ライフサイクル → 集客 → トラフィック獲得」
- セッション数（Organic Search だけにフィルタ）
- ユーザー数
- エンゲージメント率
- ページ別エンゲージメント時間

### GA4「ライフサイクル → エンゲージメント → イベント」
本サイトで計測しているカスタムイベント:
- `spot_view`（スポット詳細クリック）
- `prefecture_page_view`
- `category_page_view`
- `share_click`（X / Facebook / LINE / コピー）
- `submit_cta_click`（投稿動線クリック）
- `nearby_search_click`（現在地検索）
- `map_filter_click`（地図フィルタ操作）
- `copy_url_click`

## 2. ページ別に改善優先度を出す

GSC「検索パフォーマンス」→「ページ」タブで、過去 28 日のページ別の数字をエクスポート（または直接見る）。

並べ替えの優先順:

| 並び順 | 何のため | 次のアクション |
|---|---|---|
| **インプレッション降順** | 露出はあるけどクリックされてないページ | title / description / OGP のリライト |
| **クリック降順** | 流入を稼いでいる勝ちページ | 内部リンクを集める / シェアボタン目立たせ |
| **掲載順位 11〜20 位** | 1 ページ目に押し込めばクリックが伸びるページ | 本文の充実 / 関連ページからのリンク追加 |
| **CTR < 1%** | タイトル / 説明が刺さってない | リライト + OGP 確認 |

## 3. 典型的な改善パターン

### ケース A: インプレッションは出るがクリックが少ない
**症状**: GSC のページに表示はされるが CTR 1% 未満。
**原因の候補**: タイトルが弱い / description が説得力に欠ける / SERP の競合の方が魅力的。
**手当て**:
1. `generateMetadata()` の title/description を更新する（仕様準拠の形式維持）
2. OGP は X カードバリデータ（https://cards-dev.twitter.com/validator）と Facebook シェアデバッガ（https://developers.facebook.com/tools/debug/）で再取得
3. 1〜2 週間でリインプレッションを確認

### ケース B: クリックは入るがすぐ離脱
**症状**: GA4 のエンゲージメント率が極端に低い（< 30%）。
**原因の候補**: 本文が薄い / モバイルで読みにくい / 期待外れ。
**手当て**:
1. 該当ページに地図 / 関連スポット / カテゴリ別件数を追加
2. 投稿 CTA を上部にも置く
3. シェアボタンを目立たせる

### ケース C: 投稿 CTA を押されない
**症状**: `submit_cta_click` イベントがほぼ 0。
**原因の候補**: CTA が埋もれている / 投稿の心理的ハードルが高い。
**手当て**:
1. CTA バナーをスポット詳細・都道府県ページの上部にも配置
2. CTA の文言を「地元の噂を投稿する（30秒）」のように手間の少なさを訴求
3. 投稿フォームの最初を緯度経度ではなく地図ピックに（実装済み）

### ケース D: 海外からのアクセスがあるが英語ページが弱い
**症状**: GA4「国別」で日本以外の比率が高いが `/en` のセッション時間が短い。
**手当て**:
1. `/en/about` / `/en/submit` に英文の本格的なローカライズ
2. `/en/spots/[slug]` の英語版を将来検討（フェーズ 5）

## 4. 月次レビュー（30分）

1. GSC「インデックス → カバレッジ」: クロールされていない URL がないか
2. GSC「サイトマップ」: 全 sitemap のステータスを確認、エラーがあれば修正
3. GSC「リッチリザルト」: 構造化データのエラー（Place / Article / BreadcrumbList / FAQPage）
4. GA4「ランディングページ」レポート: 検索流入で着地するページの傾向
5. AdSense 収益（承認後）: RPM / CTR / 配置別の収益

## 5. 改善 PR のラベル付け運用

修正したら git のコミットメッセージに `seo:` プレフィックスを付けて、後で「どの修正がどこに効いたか」を追えるようにする。

例:
```
seo: rewrite /area/tokyo title to increase CTR (was 0.8%, target 2%)
seo: add internal link from category to related prefectures
seo: update OG image for /ranking — new pin layout
```

## 6. AdSense 承認後の追加施策

- 広告配置の最適化（Ad Manager で実験）
- 全ページの記事下に AdSense unit
- 高インプレッション低 CTR ページに「関連スポット」セクションを増設
- ロングテール SEO（カテゴリ × 都道府県の組み合わせページ生成検討）
